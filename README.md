# منظومة حساب الرسوم القضائية

منصة ويب مرجعية (وضع تجريبي) لتسجيل الدعاوى، اشتقاق الوعاء المالي، واحتساب الرسوم على الخادم مع مسار شرح وتدقيق.

**ليست خدمة حكومية حية.** الشعار للتعريف البصري فقط. حزمة القواعد المالية `DEMO-JFS-RELATIVE` غير موثّقة قانوناً.

## التشغيل

```bash
npm install
npm test
npm run dev
```

- الواجهة: http://localhost:5173
- واجهة البرمجة: http://127.0.0.1:8787/api/health

في وضع التطوير تُستخدم SQLite في `data/jfs.sqlite`. يضيف تحديث الأدوار حقلي البريد والهاتف وفهارس uniqueness عند تشغيل الخادم، من دون حذف بيانات الجداول الحالية.

## حسابات التجربة

| المستخدم | كلمة المرور | الدور |
| --- | --- | --- |
| `estimator` | `demo-estimator` | مقدّر رسوم |
| `supervisor` | `demo-supervisor` | مراجع مالي |
| `legal` | `demo-legal` | مراجع قانوني |
| `governance` | `demo-governance` | حوكمة القواعد |
| `leader` | `demo-leader` | قيادة تشغيلية |
| `admin` | `demo-admin` | إدارة النظام |

الحساب `admin` حساب تجربة بصلاحيات أدمن محدودة، وليس سوبر أدمن. لا تُستخدم أي حسابات التجربة خارج التطوير.

## الأدوار والبوابات

- الموظفون يحتفظون بأدوار التقدير والمراجعة والحوكمة الحالية وصلاحياتها.
- نطاق قضايا الموظف والحسابات والمراجعة مرتبط بمحكمته المسندة؛ وتظل القضايا القديمة التي أنشأها الموظف متاحة له. إنشاء القضايا الجديدة خارج المحكمة المسندة ممنوع.
- الأدمن يطّلع على مؤشرات التشغيل وسجل التدقيق، ويدير حسابات المواطنين والموظفين فقط.
- يجب إسناد محكمة عند إنشاء حساب موظف. الأدمن يستطيع إنشاء موظف لمحكمة محددة، بينما تغيير محكمة حساب قائم محصور في السوبر أدمن.
- السوبر أدمن يملك صلاحيات إدارة الحسابات الحساسة وإسناد الأدوار والمحاكم، مع منع تعطيل أو خفض آخر سوبر أدمن نشط.
- المواطن يستطيع فتح الحاسبة العامة بلا حساب؛ مدخلات القضية لا تُحفظ، ويظهر المبلغ النهائي فقط. ويمكنه اختياريًا إنشاء حساب لحفظ سجل حساب خدمات المحكمة وبيانات ملفه.

صلاحية الجلسة تُعاد قراءتها من قاعدة البيانات مع كل طلب؛ تغيير دور الحساب أو تعطيله يسري على الجلسات القائمة. عمليات إنشاء الحسابات الإدارية وتغييرها تُسجل في سجل التدقيق.

قائمة المستخدمين تدعم البحث بالاسم أو اسم المستخدم أو البريد، والتصفية حسب الدور والحالة، وصفحات خادمية بحد أقصى 100 مستخدم في الطلب. لوحة الإدارة تدعم فلاتر تاريخ الإنشاء والحالة والخدمة ودور منشئ السجل.

## إعداد أول سوبر أدمن

لا يوجد حساب سوبر أدمن أو كلمة مرور افتراضية في الكود. انسخ `.env.example` إلى `.env`، واستبدل `SESSION_SECRET` بقيمة عشوائية سرية لا تقل عن 32 حرفًا، ثم اضبط `BOOTSTRAP_SUPER_ADMIN_USERNAME` و`BOOTSTRAP_SUPER_ADMIN_DISPLAY_NAME` و`BOOTSTRAP_SUPER_ADMIN_PASSWORD` (14 حرفًا على الأقل). شغّل الخادم مرة واحدة لإنشاء الحساب، ثم احذف قيم `BOOTSTRAP_SUPER_ADMIN_*` من البيئة. لا تضع الأسرار في المستودع أو السجلات.

عند التشغيل الإنتاجي لا تُنشأ حسابات التجربة تلقائيًا، ويشترط ضبط `SESSION_SECRET`. استخدم HTTPS حتى تعمل كوكيز الجلسة الآمنة كما ينبغي.

إذا نُقلت قاعدة تطويرية إلى الإنتاج، تُرفض أيضًا حسابات التجربة المعروفة من تسجيل الدخول؛ استخدم حسابات مُدارة جديدة.

## حدود النسخة الحالية

التحليلات مصدرها سجلات القضايا والتقديرات والخدمات والمستخدمين الموجودة في SQLite. الحاسبة العامة لا تحفظ أي بيانات، وحساب الخدمة المحفوظ ليس طلبًا قضائيًا رسميًا. رسوم الخدمات وقواعد الرسوم لا تزال تجريبية وغير موثقة قانونيًا. لا يتضمن النظام بعد استعادة كلمة المرور أو مزود هوية مؤسسي أو إدارة إعدادات إنتاجية.
