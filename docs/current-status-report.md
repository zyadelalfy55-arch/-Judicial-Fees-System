# تقرير حالة التنفيذ الحالي

**تاريخ التقرير:** 8 أكتوبر 2026  
**الإصدار:** نموذج أولي تجريبي `0.1.0`  
**مرجع الحالة الحالي:** هذا التقرير يصف الكود الموجود في المستودع الآن، وليس كل ما ورد في وثيقة المواصفات.

## الملخص

المشروع نموذج أولي قابل للتشغيل محليًا: واجهة عربية RTL، API، محرك حساب، تسجيل دخول موحد للأدوار، بوابة مواطن، إدارة مستخدمين، لوحة مؤشرات، وقاعدة SQLite. أضيف نطاق وصول للقضايا حسب المحكمة، مع الحفاظ على وصول الموظف لقضاياه القديمة التي أنشأها. القواعد والأرقام تجريبية وغير موثقة قانونيًا، ولا ينبغي استخدامه لاتخاذ قرار أو إصدار مستند رسمي.

| المجال | الحالة |
| --- | --- |
| واجهة الموظف | المسار الأساسي متاح، مع حماية المسارات حسب الصلاحية |
| الأدوار | مواطن، أدوار الموظفين الحالية، أدمن، وسوبر أدمن |
| بوابة المواطن | حساب اختياري أو حاسبة عامة بلا دخول؛ الحاسبة لا تحفظ المدخلات وتعرض المبلغ فقط |
| إدارة الحسابات | إنشاء وتعطيل وتفعيل وإسناد الأدوار؛ بحث/فلترة/صفحات مستخدمين من الخادم؛ تعيين المحكمة مطلوب للموظف وتغييره للسوبر أدمن فقط |
| نطاق البيانات | قوائم القضايا والحسابات مقيدة بالمحكمة أو بكون الموظف منشئ السجل القديم |
| فلاتر لوحة الإدارة | تاريخ البداية والنهاية، حالة القضية، الخدمة، والدور؛ التجميعات تُحسب في SQLite |
| قاعدة البيانات | SQLite محلية؛ لا توجد قاعدة أو ترحيلات إنتاجية |

هذا وصف للوظائف الحالية وليس شهادة جاهزية إنتاجية أو اعتماد قانوني.

## المنفذ حتى الآن

### الواجهة الأمامية

- تطبيق React 19 وTypeScript وVite مع React Router وواجهة عربية باتجاه RTL.
- غلاف للتطبيق يتضمن تنقلًا جانبيًا، عرضًا متجاوبًا أساسيًا، حالة المستخدم، ورسائل واضحة بأن النظام تجريبي وغير رسمي.
- قائمة دخول تختار نوع الاستخدام دون أن تمنح الدور؛ الأدوار الإدارية تتحقق من جلسة الخادم، والمواطن يستطيع بدء الحاسبة دون كلمة مرور.
- لوحة أدمن وسوبر أدمن تعرض مؤشرات مجمعة فعلية، وبوابة المواطن تعرض الحسابات المحفوظة اختياريًا.
- واجهة إدارة الحسابات تتضمن الدور والحالة والمحكمة؛ إسناد المحكمة للحسابات القائمة متاح للسوبر أدمن فقط.
- صفحات دخول تجريبي، لوحة عمل، قائمة القضايا، إنشاء قضية، مساحة عمل القضية، نتيجة الحساب، سجل التقديرات، قائمة المراجعة، سجل القواعد، سجل التدقيق، قائمة المستخدمين، خدمات المحكمة، وصفحة معلومات الأمن.
- نموذج القضية يتيح إدخال بيانات أساسية ووقائع ومبلغ المطالبة والمقدم وهيكل الطلب والمرحلة ومعاملة الرسم والاستعجال.
- نتيجة الحساب تعرض البنود، الإجمالي والصافي، قاعدة الحساب، مسار الشرح، التحذيرات والمصادر، مع أزرار إرسال للمراجعة والاعتماد أو الإرجاع بحسب الصلاحية.
- بيانات الحساب تُطلب من API؛ حساب الرسوم لا يجري داخل مكونات React.

### الباك إند ومنطق النطاق

- خادم Fastify مع مسارات للصحة، الكتالوج، الدخول والخروج والجلسة، لوحة العمل، القضايا، الحسابات، المراجعات، القواعد، التدقيق، المستخدمين وخدمات المحكمة.
- تحقق مدخلات عبر Zod، صلاحيات مبنية على الأدوار والقدرات في الخادم، وجلسة JWT داخل Cookie من نوع HttpOnly.
- الجلسة تتحقق من issuer/audience/algorithm، وتُعاد قراءة حالة المستخدم وأدواره ومحكمته من قاعدة البيانات لكل طلب. الخادم يتجاهل المحكمة المرسلة من العميل عند الدخول.
- وصول الموظف إلى القضايا والتقديرات وقائمة المراجعة ولوحة العمل مقيد بمحكمته؛ وتبقى قضاياه القديمة التي أنشأها متاحة له. السجلات خارج النطاق ترجع `404`، وإنشاء قضية خارج المحكمة يرجع `403`.
- حسابات التجربة لا تُنشأ تلقائيًا في وضع الإنتاج، وتُرفض الحسابات التجريبية المعروفة ومفاتيح الجلسات النموذجية عند تشغيل الإنتاج.
- سير أساسي لإنشاء القضية وتحديثها، تشغيل الحساب، حفظ التقدير ونسخته، إرساله للمراجعة، واعتماده أو إرجاعه. اعتماد الحساب والتحقق من انتقال الحالة يجريان في الخادم، مع منع المراجع من اعتماد حسابه هو.
- محرك نطاق مستقل عن React وFastify يحسب بوحدات صحيحة من المليم، ويدعم شرائح نسبية وحدًا أدنى/أقصى ومعاملة الرسم والدفعات المقدمة وبعض تراكيب المطالبات والمستحقات.
- حساب رسوم خدمات المحكمة موجود كوظيفة مستقلة، وبياناته معلّمة بأنها تجريبية.
- سجل تدقيق بخاصية ربط SHA-256 بين الأحداث وإمكانية التحقق من السلسلة.
- حوكمة أساسية لمسودات تغييرات القواعد ومراجعتها ونشرها موجودة في خدمات الخادم؛ لا توجد حتى الآن واجهة إدارة متكاملة لها ولا محرك فعلي يقرأ إصدارات منشورة مختلفة.

### قاعدة البيانات

- قاعدة SQLite محلية باستخدام `better-sqlite3`، مع تفعيل WAL وforeign keys على الاتصال.
- الجداول الحالية: `users`, `user_roles`, `cases`, `estimates`, `reviews`, `rule_changes`, `audit_events`, `documents`, `service_estimates`.
- حفظ القضايا والتقديرات ومدخلات ونتائج الحساب كلقطات JSON، والمراجعات وتغييرات القواعد والخدمات وأحداث التدقيق.
- إنشاء حسابات التجربة وحزمة قواعد موسومة بأنها غير موثقة تلقائيًا عند خلو قاعدة المستخدمين.
- مسار ملف قاعدة البيانات قابل للضبط عبر `DATABASE_PATH`، والافتراضي `data/jfs.sqlite`.
- أعمدة البريد والهاتف وتعيينات المحكمة تُدار بإضافات schema تحفظ البيانات الحالية، مع فهارس uniqueness للبريد والهاتف وفهارس لنطاق المحكمة والمنشئ.

## ما لم يكتمل أو يحتاج استكمالًا

### الواجهة

- بناء النماذج المتقدمة كاملة: الأطراف المتعددة، الطلبات النهائية المفصلة، المستحقات، المستندات والمرفقات.
- محرر القواعد، مقارنة الإصدارات، محاكاة الأثر، وسير مراجعة/نشر كامل من الواجهة.
- فلاتر التاريخ والخدمة والحالة والمستخدم، والصفحات والترتيب والتصدير والطباعة غير مكتملة. القوائم الحالية محدودة جزئيًا من الخادم.
- القضايا والحسابات أصبحت قابلة للبحث/الفلترة والصفحات بدرجات متفاوتة؛ التصدير والطباعة غير مكتملين. لوحة الإدارة تدعم فلاتر التاريخ والحالة والخدمة والدور، ولا تدعم بعد مقارنة الفترات أو الرسوم الزمنية.
- توحيد حالات التحميل والأخطاء والفراغ والتحقق وإتاحة الوصول، وإضافة اختبارات واجهة وE2E وقياسات بصرية.

### الباك إند والأمن

- موفر هوية مؤسسي OIDC/SSO وMFA غير موجود؛ تسجيل الدخول الحالي تجريبي.
- لا توجد بعد طبقة مستودعات مستقلة أو عقود DTO موحدة لكل المسارات، ولا توجد صفحات API عامة للقوائم.
- اختبارات التكامل الحالية تحقق يدويًا على خادم وقاعدة مؤقتة؛ يلزم تحويلها إلى اختبارات API آلية مع fixtures معزولة، وتغطية أكثر لمسارات التعديل والتعطيل.
- يلزم إعداد CSP في مضيف الويب الإنتاجي؛ CSP معطّلة حاليًا في Helmet. كما يلزم اختبار CSRF/CORS/cookies في بيئة النشر الحقيقية، ومراقبة وتنبيه وإدارة أسرار.
- رفع الملفات وتخزينها الخاص وفحصها غير منفذ؛ وجود جدول `documents` لا يعني وجود مسار رفع آمن.
- لا توجد تكاملات حية مع المحاكم أو التحصيل أو ITIDA/Gov-PKI أو التوقيع الإلكتروني. الموجود لا يدعي الاتصال بها.

### القواعد القانونية والبيانات والإنتاج

- لا توجد جداول رسوم أو مصادر تشريعية موثقة ومراجعة مقدمة للمشروع. `DEMO-JFS-RELATIVE` وحزمة رسوم الخدمات قيم هندسية مؤقتة؛ كما أن محلل القاعدة يعيد الحزمة التجريبية حاليًا بدل اختيار إصدار بحسب التاريخ والنطاق.
- لا توجد قاعدة PostgreSQL إنتاجية، أو ملفات migrations، أو واجهة مستودع/محول قاعدة بيانات.
- يلزم تثبيت العلاقات والقيود والفهارس وسياسة الاحتفاظ والنسخ الاحتياطي والاستعادة، والتحقق من سلامة اللقطات التاريخية والتزامن.
- لا توجد حاليًا اختبارات تكامل قاعدة بيانات أو API، اختبارات E2E، خط CI/CD، حاويات، بيئات نشر، مراقبة أو خطة استعادة موثقة.
- يلزم مراجعة قانونية وأمنية وتشغيلية قبل استخدام أي بيانات شخصية أو أرقام فعلية.

## الاختبارات التي تم تشغيلها

- `npm test`: **ناجح، 31 اختبارًا** في 5 ملفات، تشمل الحساب، مراجعة الحسابات، الأدوار ونطاق المحكمة، الجلسات، والبحث/الصفحات على SQLite مؤقتة.
- `npm run typecheck`: ناجح.
- `npm run lint`: ناجح.
- `vite build`: ناجح.
- أُجريت تجربة API يدوية على قاعدة مؤقتة لإسناد المحكمة؛ لم تُستخدم قاعدة المشروع في إنشاء حسابات الاختبار.
- الاختبارات لا تثبت تكامل OIDC أو CSRF أو أمن النشر، ولا اعتماد صحة القواعد قانونيًا.

## تشغيل المشروع على Windows

نفّذ الخطوات من PowerShell داخل مجلد المشروع:

```powershell
cd D:\law
node --version
npm --version
npm install
npm run dev
```

يفترض أن إصدار Node.js حديث ومتوافق مع TypeScript وVite المستخدمين في المشروع. الأمر `npm run dev` يشغّل خادم التطوير والواجهة معًا. افتح:

- الواجهة: http://localhost:5173
- فحص API: http://127.0.0.1:8787/api/health

حسابات التجربة:

| اسم المستخدم | كلمة المرور | الدور |
| --- | --- | --- |
| `estimator` | `demo-estimator` | مقدّر رسوم |
| `supervisor` | `demo-supervisor` | مراجع مالي |
| `legal` | `demo-legal` | مراجع قانوني |
| `governance` | `demo-governance` | حوكمة القواعد |
| `leader` | `demo-leader` | قيادة تشغيلية |
| `admin` | `demo-admin` | إدارة النظام |

للتشغيل في نافذتين منفصلتين بدل الأمر المشترك، شغّل `npm run dev:server` في الأولى و`npm run dev:client` في الثانية. قاعدة البيانات الافتراضية تُنشأ داخل `data/jfs.sqlite` وتبقى بياناتها بين مرات التشغيل؛ لا تحذف ملفات قاعدة البيانات أو WAL/SHM لإعادة الضبط دون نسخة احتياطية.

أوامر الفحص المتاحة من جذر المشروع:

```powershell
npm test
npm run typecheck
npm run lint
npm run build
```

## الحالة المختصرة

الموجود الآن هو **نموذج أولي عامل للمسار الأساسي**: دخول تجريبي → قضية → وقائع ووعاء → حساب خادمي → تفسير → مراجعة واعتماد/إرجاع → سجل وتاريخ. المتبقي الأكبر هو اعتماد القواعد القانونية ومصادرها، استكمال واجهات وسير الحوكمة والإدارة، اختبارات التكامل والأمان، ثم تجهيز قاعدة البيانات والبنية الإنتاجية. لا تستخدم أرقام الحزمة التجريبية كرسوم قانونية.
